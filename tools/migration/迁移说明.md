# 另一个你：迁移到另一台 Mac

此包包含可用凭据和用户会话数据，为未加密的私有开发备份。用 AirDrop、移动硬盘或你自己的安全传输渠道搬运，不要上传公共仓库或公开网盘。压缩包权限为 0600；文件权限不等于加密。

## 包内内容

- `another-you/`：完整本地项目，含源码、PE、测试、package-lock、已构建 dist、网站资源及原始图片/音乐/生成记录。省略 `node_modules`，在新 Mac 按锁文件重装以适配 Intel/Apple Silicon。
- `private/workbench-config.json`：当前阿里云 Workbench profile 的真实凭据，仅导出当前 profile；未导出 Codex 账户、其他项目或无关云服务凭据。
- `private/server-snapshot.tgz`：线上 `/opt/another-you`（排除 node_modules、output）、`/etc/another-you.env`（含真实 GLM 配置）、systemd unit 和 `/var/lib/another-you`。这是在线文件快照，各文件可恢复，但并非暂停服务后的跨文件事务快照。
- `bootstrap-mac.sh`：恢复凭据与本地数据、安装 Workbench（若缺失）、安装 npm 依赖、测试和构建。
- `start-local.sh`：启动本地完整网站与 API。
- `SHA256SUMS`：包内文件校验清单；同目录的归档 `.sha256` 校验压缩包传输完整性。

## 1. 解压并准备工具

把整个目录放到例如 `~/Projects/another-you-migration`，不要仅复制源码子目录。终端进入解压后的包根目录。

需要 Node.js >=22.12、npm、Python 3 和 Bash。Mac 自带 Bash；若已有 Homebrew，可运行：

```bash
brew install node@22 python
export PATH="$(brew --prefix node@22)/bin:$PATH"
node --version
python3 --version
```

未安装 Homebrew 时也可以使用 Node.js 与 Python 官方安装包。Node 和 Python 都要在终端 PATH 内。

## 2. 校验并初始化

```bash
shasum -a 256 -c SHA256SUMS
bash bootstrap-mac.sh
```

初始化会：

1. 将线上环境文件复制为 `another-you/.env.migration`（0600）。
2. 将历史数据恢复到 `another-you/data-migration/`，重复执行不会覆盖已有开发数据。
3. 导入凭据到 `~/.workbench/config.json` 的 `another-you-migration` profile，并保留原有 profile 与当前选择；原配置有备份。连接脚本通过 `tools/.workbench-profile` 自动选择迁入凭据。
4. 按需要安装 Workbench，随后运行 `npm ci`、`npm test`、`npm run build`。

命令中不包含明文密钥。不要把 `.env.migration` 或 `private/` 的内容粘贴到聊天和日志中。

## 3. 本地启动和验证

```bash
bash start-local.sh
```

访问 `http://127.0.0.1:3000`。首页不允许创建新链接，属于产品现有设计。验证历史问卷时，把原线上专属链接的域名/IP 部分换成 `http://127.0.0.1:3000`，保留 `/sanguo/原session_id` 即可。报告、答案与次数来自恢复后的本地副本。

默认 `LLM_ENABLED=false`，新生成走算法兜底；查看已有报告不调用模型。需要验证真实 GLM 时：

```bash
LLM_ENABLED=true bash start-local.sh
```

这会使用包内带来的真实 GLM key，并可能产生 API 费用；本地次数记在本地数据，线上次数不会改变。本地启动器始终限定 `127.0.0.1` 并使用 `data-migration`，不会使用环境文件里的生产数据路径。

本地调试重复次数耗尽时，可通过服务模块创建一个新的本地测试链接；仅在本地终端、应用子目录运行：

```bash
cd another-you
node --input-type=module - <<'JS'
import path from 'node:path';
import {createSessionStore} from './services/session-store.mjs';
const store=createSessionStore({dataDir:path.resolve('data-migration')});
const session=await store.create('sanguo');
console.log(`http://127.0.0.1:3000/sanguo/${session.sessionId}`);
JS
```

修改代码后在 `another-you/` 运行 `npm test && npm run build`，重启本地服务。服务启动时计算 CSP，前端重新构建后也要重启服务。

## 4. 连接原线上服务器

在包根目录执行：

```bash
bash another-you/tools/server-connect.sh status
bash another-you/tools/server-connect.sh connect
bash another-you/tools/server-connect.sh exec 'cd /opt/another-you && pwd'
```

目标为杭州 ECS `i-bp1d8o6u6htjltdnfxxh`，默认 root；应用 `/opt/another-you`，服务 `another-you.service`，数据 `/var/lib/another-you`。连接仍依赖云端凭据有效性及账号权限。无需开放新的公网 SSH 端口。

每次 exec 是独立 shell；多行命令用 `exec-file -` 和带单引号的 heredoc，示例见 `another-you/tools/README.md`。

## 5. 后续部署原则

本包的初始化和启动不会自动部署、重启或修改线上服务。后续修改完成后，先备份线上应用，上传构建产物、变更的服务源码及 PE；依赖变化时在服务器执行 `npm ci --omit=dev`，然后重启服务并检查 `/api/health`。

不要把 Mac 的 `node_modules` 上传 Linux，也不要用本地数据副本覆盖线上 `/var/lib/another-you`；迁移包中的历史快照仅用于恢复或离线开发。不要把 `.env.migration`、服务器快照和 private 凭据目录放进 dist/public。

## 给新 Mac 上 Codex 的任务说明

> 这是另一个你三国人格问卷项目。先读包根目录的迁移说明.md 和 another-you/README.md 顶部的当前状态。使用 bootstrap-mac.sh 准备环境，用 start-local.sh 本地开发。服务器通过 another-you/tools/server-connect.sh 连接，凭据已迁入专用 profile。保持累计 3 次成功 AI 报告、失败不扣次、匿名专属链接及服务端文件持久化。不要依据 README 后半段旧历史说明恢复每日/IP 限制。不要输出凭据或把本地数据覆盖线上数据。
